# Каталог фильмов. От черновика до публикации

## Подключение

Открой в DBeaver подключение **Film App Local** и схему **public**. Локальный PostgreSQL слушает на 127.0.0.1:5433. Для проверки API открой [Swagger UI](http://localhost:8082/).

Для операций в разделе **Admin** нажми **Authorize**, выбери **adminKey** и вставь значение CATALOG_ADMIN_KEY из локального файла .env.docker. Заголовок X-Admin-Key Swagger добавляет сам. Для пользовательских запросов Packs и Library нужен отдельный bearer-токен, полученный при входе в приложение.

В .env.docker используются два секрета:

- POISKKINO_API_KEY — ключ поставщика для исходящих запросов сервера.
- CATALOG_ADMIN_KEY — ключ управления импортом и публикацией. Доступ к нему позволяет удалять карточки через синхронизацию и публиковать подборки. Храни его у редактора каталога.

После изменения ключей выполни из каталога проекта:

```powershell
docker compose --env-file .env.docker up -d backend
```

## 1. Собрать черновик в DBeaver

1. В таблице **film_packs** добавь строку с названием title и описанием description. Для платного пака выставь premium=true. По умолчанию is_published=false. Сохрани запись (Ctrl+S) и запомни id.
2. В **films** поищи название и год. Если фильм уже есть, используй его id. Для нового фильма заполни title и release_year, сохрани строку и возьми присвоенный id. Поле poiskkino_id заполняет сервер после успешной загрузки.
3. В **pack_films** добавь строку для каждого фильма. pack_id указывает на подборку, film_id на карточку, position задаёт порядок. Можно задавать 10, 20, 30 и вставлять фильмы между ними.
4. Сохрани изменения. В режиме ручной фиксации транзакций DBeaver также нажми Commit. Только после фиксации сервер увидит новые строки.

Для проверки состава открой SQL Editor. Замени 123 на фактический id:

```sql
SELECT pf.position, f.id, f.title, f.release_year, f.poiskkino_id,
       f.poster_url, f.description
FROM pack_films pf
JOIN films f ON f.id = pf.film_id
WHERE pf.pack_id = 123
ORDER BY pf.position, f.id;
```

## 2. Импортировать карточки

В Swagger открой **Admin → POST /admin/packs/{id}/sync → Try it out**, введи id и нажми **Execute**. Запрос последовательно обрабатывает сохранённый состав пака и возвращает отчёт. Для больших паков обработка может продолжаться дольше тайм-аута прокси. Состояние уже обработанных карточек сохраняется после каждого фильма.

Поиск использует название и год. Для сравнения учитываются основное, альтернативное и английское названия и список вариантов names. Регистр, лишние пробелы и различие «е/ё» игнорируются. Сравнение года точное. Совпадения считаются по уникальному ID поставщика. Сервер проверяет страницы поиска до конца или до обнаружения второго точного совпадения.

- **Одно совпадение.** Сервер получает полную карточку по ID, сохраняет ссылку на постер, короткое описание (при отсутствии — обычное описание), длительность в минутах, режиссёров, актёров, жанры и poiskkino_id. Название и год остаются в редакторской версии. Если у поставщика отсутствует отдельное поле, сохранённое значение этого поля используется дальше. Изображение загружается клиентом по poster_url.
- **Ноль или несколько точных совпадений.** Сервер полностью удаляет строку из films. Внешние ключи PostgreSQL удаляют ссылки на неё **из всех паков и пользовательских библиотек**, включая свайпы и отметки о просмотре. В отчёте и журнале останутся исходные id, название и причина. Для восстановления полной истории нужна резервная копия.
- **Год или название не заполнены.** Сервер оставляет строку для исправления и сообщает YEAR_REQUIRED или TITLE_REQUIRED.
- **Ошибка поставщика, сети или формата ответа.** Текущий фильм остаётся в базе. Исправь причину, затем повтори sync. Карточки с сохранённым poiskkino_id автоматически пропускаются в любом паке.
- **Ручная правка после импорта.** Можно отредактировать значения в DBeaver. Для намеренного повторного поиска очисти poiskkino_id и запусти sync. Тогда вновь действует правило удаления при нуле или нескольких совпадениях.

### Результаты и журнал

Ответ содержит state и массив events. Для каждого обработанного фильма возвращаются filmId, title и result. Например:

```json
{
  "state": "DONE",
  "events": [
    {"filmId": 101, "title": "Прибытие", "result": "IMPORTED"},
    {"filmId": 102, "title": "Редакторский пример", "result": "DELETED_NO_MATCH"}
  ]
}
```

DELETED_AMBIGUOUS означает удаление после нескольких совпадений. CHANGED_DURING_SYNC означает, что во время обработки изменилось название, год, привязка к паку или состояние импорта. Перепроверь запись. DONE с пустым events означает, что ожидающих карточек не было.

| HTTP | Состояние | Действие |
|---|---|---|
| 200 | DONE / PUBLISHED | Посмотреть отчёт или проверить каталог |
| 401 | UNAUTHORIZED | Проверить редакторский ключ X-Admin-Key |
| 404 | NOT_FOUND | Проверить id пака |
| 409 | BUSY | Другой импорт выполняется. Повторить позже |
| 409 | EMPTY / INCOMPLETE | Добавить фильмы или заполнить поля из отчёта публикации |
| 429 | QUOTA_PAUSED | Дождаться освобождения квоты и повторить sync |
| 503 | KEY_MISSING / PROVIDER_HTTP_401 | Проверить ключ поставщика и пересоздать контейнер после его замены |
| 503 | PROVIDER_PAUSED_403 / PROVIDER_PAUSED_429 | Импорт приостановлен на 24 часа. Проверить тариф, лимиты и права ключа |
| 503 | IMPORT_ERROR / PROVIDER_HTTP_… | Проверить сеть, доступность поставщика и журнал. Повторить позже |

Журнал импорта в PowerShell:

```powershell
docker compose --env-file .env.docker logs --since 24h backend | Select-String CatalogImport
```

## 3. Проверить готовность и опубликовать

Вызови **POST /admin/packs/{id}/publish** в Swagger. Для публикации нужен хотя бы один фильм. У каждой карточки обязательны название, год, непустые poster_url и description. Если поставщик не дал постер или описание, заполни их вручную либо убери фильм из состава пака. Публикация проверяет заполненность ссылки, а доступность картинки можно проверить, открыв её на телефоне.

При успехе сервер отвечает PUBLISHED и ставит is_published=true. GET /api/v1/packs покажет пак при следующей загрузке каталога. GET /api/v1/packs/{id}/films отдаёт карточки с учётом премиума и предыдущих свайпов пользователя.

Для снятия с публикации поставь **is_published=false** в DBeaver и сохрани. Удобно снимать пак с публикации перед редактированием. Даже при is_published=true пустой пак или пак с незаполненной карточкой автоматически скрывается. Когда все поля снова заполнены, такой пак снова появится. Для обязательного ручного выпуска после правок сначала ставь false.

При установке обновления ранее существовавшие непустые полные паки сохраняют видимость. Неполные становятся черновиками. Для проверки фактически видимых паков:

```sql
SELECT id, title, premium FROM visible_film_packs ORDER BY id;
SELECT * FROM incomplete_pack_films ORDER BY pack_id, film_id;
```

## 4. Контроль 200 запросов

Квота действует на исходящие HTTP-вызовы этого бэкенда за скользящие 24 часа. Каждый запрос поиска, дополнительная страница и загрузка карточки по ID занимают по одному месту. Попытка резервируется в PostgreSQL перед отправкой и учитывается даже при ошибке сети. Одновременно выполняется один импорт на базу. После перезапуска сервера учёт сохраняется. Свайпы, выдача каталога и публикация пака квоту не используют.

При исчерпании лимита незавершённые карточки остаются в очереди для следующего ручного запуска. Чтобы видеть расход и ближайшее освобождение места:

```sql
SELECT count(*) AS used, 200-count(*) AS remaining,
       min(requested_at) + interval '24 hours' AS next_slot_expires_at
FROM poiskkino_requests
WHERE requested_at > now() - interval '24 hours';
SELECT blocked_until FROM poiskkino_quota;
```

Если ключ используется из других программ или второй копии сервера со своей БД, эти запросы видит только поставщик. Для предсказуемого ограничения используй один активный импортёр на ключ.

## 5. Перенос на VPS

Перенеси PostgreSQL через резервную копию и восстановление, включая таблицы импорта и учёта запросов. Перед переключением останови импорт на старой машине. Размести .env.docker на VPS с ограниченными правами чтения и запусти docker compose --env-file .env.docker up -d --build. Серверу нужен исходящий HTTPS-доступ к api.poiskkino.dev. При чистой установке миграции создадут четыре демонстрационных пака как черновики.

Для удалённого администрирования используй Swagger через SSH-туннель на loopback-порт 8082 или через закрытый HTTPS-вход. На публичном прокси приложения направляй пользовательские запросы /api/v1/; доступ к /admin/ предоставляй только редакторам. Из контейнера Ktor редакторские запросы принимаются на том же порту, что и пользовательские. Ограничь внешний доступ к опубликованному Docker-порту на VPS. Для DBeaver можно использовать SSH-туннель к 127.0.0.1:5433.

Данные о фильмах предоставляет [ПоискКино](https://poiskkino.dev/documentation). Секреты находятся в окружении сервера. Android продолжает получать карточки через PacksApi и LibraryApi.

## Локальная обложка и прогресс

Положи изображение в папку media/pack-covers в проекте на машине с Docker. При создании пака укажи в film_packs.cover_file одно имя файла, например weekend.jpg. Допустимы латинские буквы, цифры, дефисы и подчёркивания и расширения png, jpg, jpeg, webp в нижнем регистре. Начни имя с буквы или цифры. По умолчанию используется default.png. Можно добавить файл и изменить имя через DBeaver без сборки и перезапуска сервера. Для замены уже показанной картинки лучше использовать новое имя, чтобы обновился кеш Android.

Проверь файл в браузере по адресу http://localhost:8081/api/v1/pack-covers/weekend.jpg. На VPS перенеси также сам каталог media/pack-covers вместе с резервной копией PostgreSQL. Содержимое каталога монтируется в контейнер только для чтения.

В списке паков coverUrl содержит путь от корня сервера. Флаг isCompleted рассчитывается для текущего аккаунта: у каждого фильма в паке есть решение в библиотеке. Статусы WILL_WATCH, WONT_WATCH и WATCHED равнозначны при расчёте. Удаление решения может снова открыть пак. Добавляй один и тот же фильм в разные паки через его существующий film_id. Для отдельно импортированных копий сервер также сверяет poiskkino_id.
